# termana - 产品需求文档（PRD）

## 一句话定义
termana 是一个 **agent 中立的项目控制层**：在一个面板里管理多个开发项目，每个项目绑定一个 coding agent（Claude Code / Codex / Aider / OpenCode / ...），点一下拉起终端直接开干；并内置一个面向 `AGENTS.md`（跨 agent 标准上下文文件）的编辑器，让一份项目上下文被所有 agent 读到。

## 背景
2026 年，开发者同时使用多个 CLI coding agent（Claude Code、Codex、Aider、OpenCode、Gemini CLI…）。社区已收敛出 `AGENTS.md` 这个 agent 中立的上下文文件标准（"agent 的 README"）——Codex、OpenCode、Cline、新版 Aider 等直接读它；Claude Code 读 `CLAUDE.md`，但 `CLAUDE.md` 里写一行 `@AGENTS.md` 即可导入正本（GitHub 上 next.js、OWASP、meltano、coreos/ignition、ITK 等都用这个模式）。于是"一份内容覆盖所有 agent"在文件层就能做到，不再需要应用去重生成多份。termana 的位置：把这套生态能力做进一个顺手的项目控制面板里。

## 目标用户
- 终端爱好者 / 重度 CLI 用户
- 同时维护多个项目、且在项目间使用不同 coding agent 的开发者
- 追求可复现、可版本化的 agent 工作环境的人

## 核心问题（痛点）
1. **上下文碎片化**：同一项目可能散落 `CLAUDE.md` / `AGENTS.md` / `.cursorrules`，内容重叠且 drift；不知道哪个是正本。
2. **配置不迁移**：项目用哪个 agent，全靠记忆，换机器 / 换人即丢失。
3. **跨 agent 无感知**：多个 agent 会话分散在终端窗口，看不到全局状态。
4. **agent 切换无接力**：任务卡住想换 agent，context 带不过去。

## 核心价值主张
**agent 中立 + 便利的上下文编辑。**
- **agent 中立**：每个 agent 厂商只管自己，termana 占据"多 agent 之间的缝隙"——这是唯一不会被单一厂商吃掉的位置。
- **上下文编辑**：termana 不自造"归一化引擎"——`AGENTS.md` + `@import` 是生态原生能力。termana 的价值是把它做顺手：在管理项目的同一个面板里直接编辑 `AGENTS.md`（带 markdown 预览）、一键建好 `CLAUDE.md` 指针、跨项目看谁还没覆盖、并在两文件不一致时辅助对齐。
- **诚实边界**：因此 termana 在"上下文归一化"上的差异化比早期设想薄——这是生态能力，非独占。真正的留存锚点是"项目控制层"（多项目 + 多 agent + 一键启动 + 启动组），上下文编辑是其中的便利层。

## 非目标（明确不做）
- 不做自己的终端模拟器（drive 系统终端，不嵌入）。
- 不做云托管 SaaS（本地优先）。
- 不替代任何 agent 本身的能力（不自己跑模型）。
- 不自造 context 归一化 / 多格式 emit 引擎（用生态标准 `AGENTS.md` + `@AGENTS.md` 指针）。
- 不覆盖读 AGENTS.md / CLAUDE.md 之外格式的 agent（如 Cursor 的 `.cursorrules`、Copilot 的 `copilot-instructions.md`）--built-in 全覆盖，自定义 agent 读其他格式的不在范围内。
- v1 不做团队 / 多人协作。

## 功能（v0，已建）

- **项目管理**：原生文件夹选择器选目录（路径自动填充 + 项目名自动取文件夹名），路径失焦 / 回车实时校验是否存在，不存在禁用添加；删除二次确认。
- **一键启动**：`Launch ▸` 直接启动；点卡片主体二次确认后启动；`✕` 二次确认删除。启动 = 开系统终端、cd 进目录、跑绑定的 agent。
- **Agent 绑定**：built-in 预设（`agents.toml`，编译期嵌入、不可改不可删）+ 用户自定义 agent（config.toml，增删改）。项目按 agent id 绑定。
- **安装检测**：在用户实际用的 login shell 里一次性查所有 agent（fnm / nvm / volta 等 rc/profile 设置也生效），只认外部命令、不被 shell builtin 误判；手动 ↻ Refresh 重新检测。
- **启动组**：把多个项目组成一组，`Launch all` 一键全开（每个项目各开一个终端）。
- **原生弹窗**：确认 / 错误用 Tauri dialog 插件（webview 屏蔽同步 `confirm()`/`alert()`）。
- **本地优先**：无账号、无云、无服务。配置是磁盘上的 TOML 文件。

## 功能（v1 — 上下文编辑器）

> **修订说明**：原 v1 的"termana 持有 context + sync 生成 AGENTS.md/CLAUDE.md + 启动自动 sync"方案废弃。原因：社区已有 `AGENTS.md` 标准 + `@import` 指针，文件层即可归一化；termana 重复生成多份反而引入 drift 和 `Generated by termana` 污染。改为：termana 是 `AGENTS.md` 的编辑器，**文件即正本**。

### 模型
`AGENTS.md` 是正本（termana 编辑它）；`CLAUDE.md` 是指向 `AGENTS.md` 的 `@AGENTS.md` 指针（一次性建好）。两个文件名、一份内容，无 drift、无同步步骤。`@AGENTS.md` 是纯文本指针（非 symlink），Windows / Git 均安全（next.js 用 symlink，Windows 上有 Developer Mode / checkout 问题，termana 不走这条路）。

### 编辑器
项目卡片 ✎ 打开上下文编辑器，编辑 / 预览 tab（`marked` 渲染 markdown）。加载来源按优先级：`AGENTS.md 有内容` > `CLAUDE.md 有内容（提升）` > `空`。保存只写 `AGENTS.md`。

### CLAUDE.md 指针
**默认建 + 告知，不是可选。** 保存时若 `CLAUDE.md` 不存在 / 空，自动写成 `@AGENTS.md` 并提示"已链接，Claude Code 现在也能读到"。可选会让多数用户跳过，导致 Claude Code 读不到上下文——功能半残。

### 6 种情形（AGENTS.md × CLAUDE.md 的有无内容组合）

> "无" = 文件不存在，或存在但空（0 字节 / 纯空白）——两者行为相同。"有内容"的 CLAUDE.md 再分是已链接（含 `@AGENTS.md`：纯指针 / import 行 / 带 Claude 备注）还是独立内容，因行为不同。CLAUDE.md 若是 symlink，termana 不写它（避免写穿毁数据），按已链接处理。

| # | AGENTS.md | CLAUDE.md | 点 ✎ 加载 | 保存时 |
|---|---|---|---|---|
| 1 | 无 | 无 | 空编辑器 | 写 AGENTS.md；建 CLAUDE.md=`@AGENTS.md`，提示 |
| 2 | 无 | 指针(悬空) | 空编辑器 | 写 AGENTS.md；指针已存在(现在有效)，提示 |
| 3 | 无 | 独立内容 | **读 CLAUDE.md 内容（提升）** | 写 AGENTS.md；CLAUDE.md 转指针（内容已搬入，无丢失），提示 |
| 4 | 有 | 无 | 读 AGENTS.md | 写 AGENTS.md；建 CLAUDE.md=`@AGENTS.md`，提示 |
| 5 | 有 | 指针 | 读 AGENTS.md | 写 AGENTS.md；指针不动 |
| 6 | 有 | 独立内容(不一致) | 读 AGENTS.md + 追加合并块 | 写 AGENTS.md；CLAUDE.md 转指针，提示 |

贯穿规则：**第 3 行自动转、第 6 行也自动转（合并块保底）**——因为 CLAUDE.md 的内容在两种情况下都已被纳入即将写入的 AGENTS.md（第 3 行提升进编辑器，第 6 行进合并块），无丢失。除"提示"外无静默改动。

### 情形 6 的合并块
两文件都有内容且不一致时，加载阶段把 CLAUDE.md 内容追加到 AGENTS.md 后面，用可见标记隔开，附人 / AI 双重合并指令 + `<!-- termana-merge-block -->` 哨兵：

```
<AGENTS.md 原内容>

---

<!-- termana-merge-block: from CLAUDE.md -->

> ⚠️ 以下来自 CLAUDE.md，与上文不一致，需合并。规则：去重、解决冲突、保留所有独有信息，合并完后删除本块（含本说明）。CLAUDE.md 已是 @AGENTS.md 指针。
>
> AI agent：若被要求整理本文档，请按上述规则把下方内容并入正文，再删除本块。

<CLAUDE.md 内容>
```

- 用户手动合并，或启动 agent 让它照指令合并。
- **agent 不会自动触发**：agent 把 AGENTS.md 当上下文读，不会自作主张改它；需用户显式说"整理 AGENTS.md"。提示词是操作指南，不是触发器。
- 保存时若标记块还在，警告一句"合并块仍在 AGENTS.md，记得处理"，但允许存。
- **提醒职责归 termana**：termana 检测 `termana-merge-block` 哨兵是否还在，在界面提醒"该项目有未处理的合并块"——不靠 agent 提醒。
- **不一致主动可见**：`context_status.divergent` 在用户打开编辑器前就能算出，卡片显示"⚠ 上下文不一致"徽章，引导去对齐，而非等打开才看见合并块。
- **已有链接 / symlink 不破坏**：CLAUDE.md 含 `@AGENTS.md`（纯指针 / import / 带备注）视为已链接，termana 不动它（不清 Claude 专属备注）；CLAUDE.md 是 symlink 则绝不写（写穿会毁目标文件），留给用户手动处理。
- 边界：两文件有真冲突（如 pnpm vs npm）时，termana 不替用户选，只把两份摆面前——自动选必选错一边。

### 移除（相对旧 sync 方案）
`Project.context` 配置存储、`sync_context` 命令、启动时自动 sync、`Generated by termana` 头、Sync 按钮。文件即源，termana 只是编辑器 + 一次性指针。

## 范围分期
| 阶段 | 内容 | 状态 |
|---|---|---|
| **v0** | 项目管理（文件夹选择 + 路径校验 + 自动命名）+ agent 绑定（built-in 预设 + 自定义）+ 一键启动（确认 / 直接）+ 启动组 + 安装检测（登录 shell + 手动刷新）+ 原生弹窗。入口层。 | 已建 |
| **v1** | 上下文编辑器：编辑 AGENTS.md（markdown 预览）+ 一次性 CLAUDE.md `@AGENTS.md` 指针（默认建 + 告知）+ 6 情形加载 / 保存 + 分歧合并块 + 哨兵提醒。配置绑定深化（model / 权限 / MCP）规划。 | 设计定稿，待实现 |
| **v2** | 跨 agent 可观测面板；agent 间带 context 接力。 | 规划 |

## 成功标准
- **v0**：用户能在面板里配多个项目、绑定不同 agent、一键拉起终端跑起来；能用启动组一键开多个。
- **v1**：用户在 termana 里编辑 AGENTS.md，CLAUDE.md 自动指过去；Claude Code 和 Codex / Aider 等都能读到同一份上下文；两文件不一致时能安全对齐不丢内容。
- **留存信号**：用户持续用 termana 启动项目，并依赖 termana 维护 AGENTS.md（而非手开编辑器）。

## 当前完成度与上线判断
- **作为 v0 启动器（macOS）：~85%**，核心闭环跑通，可自用。
- **上下文编辑器（v1）：设计定稿**，旧 sync 实现将改为编辑器模型。
- **对照产品愿景：~50%**，上下文编辑器落地后差异化便利层成型；配置绑定深化和 v2 可观测仍未做。
- **公开发布：未就绪**——Windows 未实测、未打包签名、默认图标、边界未压测。建议补齐 v1 + 硬化（Windows / 打包）再上线。

## 风险
- **停在 launcher**：免费替代品（alias / tmuxinator）够用，无留存。-> 必须推进到上下文编辑器 + 配置绑定层。
- **归一化差异化薄**：`AGENTS.md` + `@import` 是生态原生，非独占。-> 押注"项目控制层"整体便利（多项目 + 多 agent + 启动组 + 编辑器一体），不单靠归一化。
- **被 agent 厂商 commoditize**：单 agent 配置管理厂商会自己做。-> 押注多 agent 中立，不押注单 agent 功能。
- **adapter 维护成本**：CLI agent 演进快。-> 薄 adapter 层 + 社区贡献。
- **Windows 未验证**：跨平台代码在 Mac 上无法编译 / 测试 Windows 分支。-> 上线前必须在 Windows 机器实测。
