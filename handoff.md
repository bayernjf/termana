# termana · Handoff

> Last updated: 2026-08-03 (v1 context redesign: sync model → editor model; design finalized, code change pending).

## What it is

termana is an **agent-neutral project control layer**. A Tauri desktop app where you register projects, bind a coding agent (Claude Code / Codex / Aider / OpenCode / custom) to each, and launch with one click - a terminal opens, `cd`s into the project, and runs the agent. You can also group projects and launch them all at once. It also includes a context editor for the project's `AGENTS.md` (the cross-agent standard context file).

Local-first: no account, no cloud, no server. Config is a TOML file on disk.

## Status

**v0 (launcher) - done & pushed.** **v1 context feature - built as a sync model, now being redesigned to an editor model.** See [docs/PRD.md](docs/PRD.md) and [docs/technical-design.md](docs/technical-design.md).

### What works (in code now)
- **Projects**: add (native folder picker, path validation, name auto-filled from folder), remove, launch.
- **Project launch**: `Launch ▸` hint = direct launch; clicking the card body = confirm-then-launch; `✕` = confirm-remove.
- **Agents**: built-in presets from [agents.toml](agents.toml) (immutable, compile-time embedded) + user-defined custom agents (config, mutable). Install detection via a login shell (fnm/nvm/asdf/volta aware), with a manual ↻ Refresh button.
- **Launch groups**: group multiple projects, `Launch all ▸` opens a terminal per project.
- **Dialogs**: native Tauri confirm/message dialogs (sync `confirm()`/`alert()` are blocked by the webview).
- **Context (v1, OLD sync model - committed)**: per-project `Project.context` (markdown) edited via ✎; `sync_context` writes it to `AGENTS.md` + `CLAUDE.md` with a `Generated by termana` header; auto-syncs on launch; `ctx` badge.
- **Markdown preview (uncommitted)**: edit/preview tabs in the context editor, rendered via `marked`.

### Pending redesign (design done in docs, code NOT yet changed)
The sync model is being **replaced** by an editor model. Reason: the ecosystem already has `AGENTS.md` (the agent-neutral standard, read by Codex/OpenCode/Cline/recent Aider) + `@AGENTS.md` import (Claude Code reads `CLAUDE.md`, which imports AGENTS.md). GitHub projects (next.js, OWASP, meltano, coreos/ignition, ITK) already do "one canonical AGENTS.md + CLAUDE.md pointer" at the file level - termana regenerating multiple files causes drift and `Generated by termana` pollution.

**New model**: termana is a text editor for `AGENTS.md` (the file is the source). `CLAUDE.md` is a one-time `@AGENTS.md` pointer (default-created + informed, not optional). No sync, no auto-sync, no generated header, no Sync button.

Implementation per [docs/technical-design.md](docs/technical-design.md) §5:
- **Remove**: `Project.context` field, `get_context`/`set_context`/`sync_context`, `write_context_files`, auto-sync in `resolve_and_launch`, `Generated by termana` header, Sync button.
- **Add commands**: `read_context` (load - priority AGENTS.md > CLAUDE.md > empty), `save_context` (write AGENTS.md + handle CLAUDE.md pointer), `context_status` (badge + merge-block reminder).
- **6-case load/save matrix** (AGENTS.md × CLAUDE.md states) - see PRD. Case 3 promotes CLAUDE.md content; case 6 (divergent) appends a `<!-- termana-merge-block -->` merge block for human/AI reconciliation.
- **Failure handling**: write AGENTS.md first (canonical); AGENTS.md fail = `Err` (nothing changed); CLAUDE.md fail = partial success (content safe in AGENTS.md, retryable, self-healing).
- **Edge-case guards** (data-loss prevention):
  - CLAUDE.md "linked" = contains `@AGENTS.md` (pure pointer / import line / with notes) - don't clobber Claude-specific notes (egg/coreos pattern).
  - CLAUDE.md is a symlink → never write (`symlink_metadata` check; `fs::write` writes through symlinks and would corrupt the target - next.js pattern).
  - `read_context` won't re-append a merge block if the sentinel already exists (prevents duplication).
- **UX**: `divergent` badge on card before opening editor; Cancel warns on unsaved (dirty) changes; symlink-skip toast.

## Run

```bash
npm install
npm run tauri dev      # dev app on http://localhost:1442
npm run tauri build    # release binary
```

Prerequisites: Rust, Node.js, Xcode CLT (macOS).

**Note:** dev server uses port **1442** (not Tauri default 1420; 1420 was occupied on the dev machine). Configured in [vite.config.ts](vite.config.ts) and [src-tauri/tauri.conf.json](src-tauri/tauri.conf.json) `devUrl`.

## Config

- macOS: `~/Library/Application Support/termana/config.toml`
- Windows: `%APPDATA%\termana\config.toml`

```toml
[[projects]]
id = "my-app"
name = "My App"
path = "/Users/me/projects/my-app"
agent = "claude"

[[groups]]
id = "backend"
name = "Backend"
project_ids = ["my-app", "api-server"]

[[agents]]        # user-defined (custom) agents only
id = "gemini"
name = "Gemini"
command = "gemini"
```

Built-in presets are **not** in this file - they come from [agents.toml](agents.toml) (root), embedded at compile time via `include_str!`.

> The `Project.context` field (currently in the sync model) is **slated for removal** in the editor-model redesign - the file (AGENTS.md) becomes the source of truth.

### Key flows
- **Launch project**: `launch_project(id)` -> `resolve_and_launch` finds the project, resolves the agent command (built-in > custom > raw id), calls the platform terminal adapter -> opens terminal, `cd` + run. (Current code auto-syncs context before launch; the redesign **removes** this - launch only opens the terminal.)
- **Launch group**: `launch_group(id)` -> loops the group's project_ids, `resolve_and_launch` each -> one terminal per project.
- **Install detection**: `list_agents` -> `installed_status(commands)` runs one login shell (`$SHELL -ilc` on unix, `powershell -Command` on Windows) checking `command -v` / `Get-Command -CommandType Application` for every agent. Only external commands count - shell builtins like `continue` are not mistaken for installed agents.
- **Context (current sync)**: `get_context`/`set_context` read/write `Project.context`; `sync_context` writes it to AGENTS.md + CLAUDE.md. **Being replaced** by the editor model (`read_context`/`save_context`/`context_status`) - see [docs/technical-design.md](docs/technical-design.md) §5.

## Gotchas / key decisions

- **Sync dialogs are blocked**: Tauri v2's webview does not show synchronous `confirm()`/`alert()`. All confirms/alerts use `@tauri-apps/plugin-dialog` (`confirm`/`message`), with `dialog:default` capability in [src-tauri/capabilities/default.json](src-tauri/capabilities/default.json).
- **Install detection must use a login shell**: a plain `which` misses tools whose PATH is set in rc/profile (fnm puts `claude`/`codex` in `.zshrc`). Detection runs `$SHELL -ilc` so it matches what the launched terminal sees. Works in both `tauri dev` and a packaged app.
- **Built-in vs custom agents**: built-ins (agents.toml) are immutable in the UI (no edit/delete, marked `built-in`); custom agents (config.toml) are fully editable. `list_agents` merges both; `update_agent`/`remove_agent` reject built-in ids.
- **Agent list columns are fixed-width** so built-in tag / install status / actions line up across rows.
- **Windows terminal code is unverified** (developed on macOS; `#[cfg(target_os="windows")]` branch is skipped here). Needs a real Windows test.
- **Context: file is the source, not sync** (redesign): `AGENTS.md` is canonical; `CLAUDE.md` is a one-time `@AGENTS.md` pointer. No `Project.context`, no sync, no generated header. The ecosystem's AGENTS.md + @import already normalizes at the file level.
- **`@AGENTS.md` pointer is plain text, not a symlink**: Windows/Git-safe (symlinks need Developer Mode on Windows and break on Git checkout). next.js uses symlinks; termana doesn't.
- **CLAUDE.md "linked" detection is broad**: contains `@AGENTS.md` (pure pointer / import line / with notes). A narrow "file is exactly @AGENTS.md" check would clobber Claude-specific notes (the egg/coreos pattern).
- **Never write a symlinked CLAUDE.md**: `fs::write` writes through symlinks and would corrupt the target (a CLAUDE.md→AGENTS.md symlink would turn AGENTS.md into a self-referential `@AGENTS.md`). Check `symlink_metadata` first; report `symlink-skip`.
- **termana owns the merge reminder, not the agent**: the `termana-merge-block` sentinel is detected by termana for UI reminders. An AI agent won't auto-merge just from reading the prompt - the user must ask it. The prompt is a guide, not a trigger.
- **Coverage boundary**: AGENTS.md + CLAUDE.md covers only agents that read one of those files. All built-ins are covered; a custom agent reading `.cursorrules` / `copilot-instructions.md` / `CONVENTIONS.md` is not.
